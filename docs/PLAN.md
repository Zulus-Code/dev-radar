# План: нативный радар GitHub-проектов для Linux

## 1. Цель

Личный настольный инструмент, чтобы без браузера находить на GitHub интересные проекты и идеи:
тренды, свежие репозитории, ниши без конкуренции. Удобные фильтры, русский интерфейс,
нативное окно Linux.

Не продукт для рынка. Один пользователь, одна машина, быстрые итерации.

## 2. Исходная точка

| Параметр | Значение |
|---|---|
| База | форк [`Zulus-Code/dev-radar`](https://github.com/Zulus-Code/dev-radar) ← `plamen5rov/github-dashboard` |
| Лицензия | MIT |
| Стек | React 19, TypeScript, Vite 7, Tailwind 3, TanStack Query 5, React Router 7 |
| Объём | 6 126 строк TS/TSX в 30 файлах |
| Тесты | 167 тестов в 13 файлах — **все зелёные** (проверено) |
| Сборка | проходит, бандл ~120 КБ gzip, 5 runtime-зависимостей |
| Готовые фичи | тренды Today/Week/Month, 6 сортировок, фильтры (язык/лицензия/топики/min stars/archived/forks), 10 developer-фильтров, букмарки, коллекции, ignore-list, URL-состояние, тёмная/светлая тема |
| Чего нет | русского языка, настоящих трендов (прирост звёзд), CI, нативной обёртки |

Апстрим-ветка — `master`. `upstream` уже прописан в локальном клоне.

## 3. Целевая архитектура

```
Tauri 2 (Rust 1.99) ── окно GTK/WebKitGTK
   └── React 19 + TS + Vite (тот же фронт)
         ├── GitHub REST (search) + GraphQL (обогащение) — напрямую, CORS разрешён
         └── SQLite через tauri-plugin-sql — снапшоты звёзд, локальные настройки
```

Ключевые решения:

- **Tauri 2, а не Electron.** Бинарь ~8–10 МБ против ~150 МБ, системный WebKitGTK вместо
  встроенного Chromium. Это и есть «нативный клиент Linux».
- **Без бэкенда на VPS.** Всё работает локально: CORS у `api.github.com` открыт
  (`access-control-allow-origin: *`, `Authorization` разрешён в preflight — проверено),
  а история звёзд хранится в локальной SQLite.
- **Токен — в SQLite/`plugin-store`, не в localStorage.** localStorage в WebView переживает
  перезапуск, но лежит открытым текстом в профиле WebKit.
- **Русский — свой словарь, без i18n-библиотеки.** Двухъязычность (ru по умолчанию, en как
  запасной) на ~350 строках текста не оправдывает зависимость. Оценка объёма: 344 строковых
  кандидата в 30 файлах.

## 4. Фазы

### Фаза 0. Фундамент: CI и честные сортировки

**Статус: выполнено.** CI зелёный на `chore/phase-0-ci` (run `41284968547`, 52 с), 165 тестов.

Задачи:
- `.github/workflows/ci.yml`: `npm ci` → `lint` → `typecheck` → `test` → `build` на Node 22.
- Локально на Node 26 тесты падают: Node притащил экспериментальный `localStorage`, он
  перебивает jsdom. Обход: `NODE_OPTIONS=--no-experimental-webstorage` в npm-скрипте тестов.
- `.nvmrc` / `engines` — зафиксировать версию Node.
- Починить две врущие сортировки (см. `CODEBASE.md`, дефекты 1–2): либо реализовать
  клиентскую сортировку по PR/issue, либо убрать опции из UI.

Готово, когда: CI зелёный на push, 167 тестов проходят, ни одна опция сортировки не врёт.

### Фаза 1. Нативная обёртка Tauri

**Статус: выполнено.** Окно запущено на реальном X11, данные GitHub загрузились; `.deb` 5 МБ, AppImage 82 МБ.

Задачи:
- `src-tauri/`: Cargo-проект, `tauri.conf.json` (`devUrl: http://localhost:5173`,
  `frontendDist: ../dist`), идентификатор `top.zulus.devradar`.
- `BrowserRouter` → `HashRouter` в `src/App.tsx` — одна строка.
- Внешние ссылки на карточках — через `@tauri-apps/plugin-opener` (2.7.2), иначе откроются
  внутри окна и пользователь потеряет приложение.
- Иконки приложения (из `public/` + генерация набора через `tauri icon`).
- Сборка `deb` и `AppImage`.
- Системные зависимости (ставятся один раз): `libwebkit2gtk-4.1-dev`, `libgtk-3-dev`,
  `libayatana-appindicator3-dev`, `librsvg2-dev`, `patchelf`. Rust 1.99.1 уже стоит.

Готово, когда: `.deb` ставится на Mint 22.2, окно открывается без терминала, поиск,
фильтры, букмарки и тема работают; внешние ссылки уходят в системный браузер.

### Фаза 2. Русский интерфейс

Задачи:
- `src/lib/i18n.ts`: словарь `ru`/`en`, функция `t(key)`, React-контекст, переключатель
  в настройках. Язык по умолчанию — `ru`, выбор хранится в SQLite/store.
- Вынести текст из 30 файлов. Основные: `pages/Home.tsx` (36), `components/FilterSidebar.tsx` (28),
  `pages/Settings.tsx` (18), `components/CollectionsPanel.tsx` (17), `components/RepoCard.tsx` (17),
  `components/BookmarksPanel.tsx` (14), `lib/constants.ts` (27 — подписи сортировок, фильтров,
  лицензий), `lib/developerFilters.ts` (45 — названия и описания фильтров),
  `lib/licenseLegend.ts` (37 — пояснения лицензий).
- Относительное время (`date-fns`) — локаль `ru` (`formatDistanceToNow` с `locale: ru`).
- Обновить тесты, которые ищут английский текст.

Готово, когда: в приложении нет английских подписей в основных сценариях, переключение ru/en
работает, тесты зелёные.

### Фаза 3. Настоящие тренды: снапшоты звёзд

**Спецификация механики: [`TRENDS.md`](./TRENDS.md)** — схема БД, кого отслеживаем, частота
синка, формула дельты, ограничения. Источник истины для реализации.

Решения, зафиксированные 2026-11-01:

- Трекинг = всё, что показывалось в выдаче за 30 дней (источник `seen`) ∪ топ-300 по
  дефолтным фильтрам (`top`), потолок 2 000 репозиториев.
- Синк при запуске приложения, не чаще раза в 6 часов; батчи по 50 через GraphQL.
- Окно дельты понижается автоматически: 7 дней → весь доступный период → «нет данных».
  Это закрывает разрыв «первую неделю трендов нет».
- Сырые снапшоты хранятся 180 дней (~15–20 МБ на 2 000 репозиториев).
- Без PAT тренды не работают: GraphQL недоступен, анонимный REST не тянет объём.
  UI показывает подсказку, остальной функционал не страдает.
- Засев истории задним числом не делаем (stargazers API — 100 звёзд на страницу).

Готово, когда: сортировка «Растущие» работает на реальных данных, история переживает
перезапуск и обновление приложения, а поведение совпадает с `TRENDS.md`.

### Фаза 4. Заточка под себя

**Статус: выполнено (2026-11-01).**

- Три встроенных пресета: «Молодой проект» (`created:>90d`, 10–500★, сортировка по обновлению),
  «Good first issue» (`good-first-issues:>0`, 10–2000★), «Без звёздного лидера» (50–2000★, месяц).
  Qualifiers проверены на живом API: 59k / 45k / 125k результатов.
- Свои пресеты: текущий набор фильтров и сортировки сохраняется под именем (до 20 штук),
  применяется заменой URL, удаляется крестиком. Хранится в `userPreferences`.
- Вид: 4 акцентных цвета и две плотности (обычная/компактная) через CSS-переменные.
- Перевод описаний репозиториев внешним LLM — **отложен**: нужны ключи, бюджет и кэш;
  отдельное решение, не входит в фазу.

### Фаза 5. Упаковка

- Автозапуск (`.desktop` в `~/.config/autostart`), иконка в меню.
- `tauri-plugin-updater` — только если понадобятся обновления; для локальной сборки не нужен.
- `README.md` под себя, `AGENTS.md` на английском с контрактом разработки.

## 5. Риски и ограничения

| Риск | Что делаем |
|---|---|
| WebKitGTK рендерит иначе, чем Chrome (`backdrop-blur`, тени) | проверяем на живом окне в Фазе 1, правим CSS точечно |
| Нет официального trending API | снапшоты; дельта появляется не мгновенно |
| Лимиты GitHub: search 30/мин с токеном, core 5 000/ч | кэш TanStack + батчинг GraphQL + локальные снапшоты |
| Форк публичной репы нельзя сделать приватным | репозиторий остаётся публичным; секретов в нём нет |
| Токен в WebView | переносим в SQLite/store, не в localStorage |
| Node 26 ломает jsdom-тесты | фиксируем Node 22 в CI, флаг локально |

## 6. Чего в плане нет

- Бэкенда на VPS, аккаунтов, синхронизации между устройствами.
- Мобильной версии.
- Перевода README чужих проектов целиком (только описания по кнопке, и то под вопросом).
- Поддержки Windows/macOS — собираем под Linux.
